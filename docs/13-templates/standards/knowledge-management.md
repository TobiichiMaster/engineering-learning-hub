# 2. 稳定编号与命名

保留已有 PY-001 至 PY-030、CS-OS/ARCH/NET/DS/ALG/DB-xxx 的 52 个 ID，不重编号、不复用。新增 Python 知识点从 PY-031 起，CS 各子类按已有最大序号递增；其他学科采用 JAVA-xxx、SPR-xxx、AGENT-xxx、INFRA-xxx、ENG-xxx。先搜索 ID 与同义主题，再分配；编号不代表课程顺序。

课程 ID 独立于知识点 ID，例如 PY-U01-L01；单元 PY-U01；练习 PY-U01-L01-EX01；实验 EXP-20261126-001；错题 ERR-20261126-001；日志 LOG-20261126-001。跨日或跨课程保留原 ID，新增证据使用新 ID。编号示例不是已创建记录。

# 3. 最小元数据与关联

正式笔记至少有 ID、标题、学科/分类、标签、课程 ID、创建日期、更新日期、版本、状态、证据链接、参考来源。涉及行为差异注明语言/框架版本与环境；未知写待确认。日志记录实际时长（未提供则未知）、已学内容、产出、未解决问题和下一行动；实验记录环境、命令、输入、实际输出、复现与局限；错题记录原答、错误原因、修复、复测结果和下次日期。

复用[知识笔记](https://chatgpt.com/space/page_e90ea058848481918f94c4323c432a5d)、[每日学习日志](https://chatgpt.com/space/page_5c83b67a9f1c81918bedbcda7b0a98fa)、[技术实验](https://chatgpt.com/space/page_ae5c09e4503081919805a0744e8c9c30)、[错题记录](https://chatgpt.com/space/page_93b1793280448191a1759d24c8148794)四个模板，不重建已有模板。

# 4. 增量归档协议

1. 确认目标 Space 和分区，查标题、ID、别名及相关子页；遇到重名不擅自合并。

2. 读取当前文档及版本，对照本次新增证据，保留不相关内容、原始评估和用户修改。

3. 有同主题则增量更新，无则创建；记录变更原因、日期、来源。修订事实时保留必要的纠错历史。

4. 更新关联日志、复习条目及当前进度；部分失败时列出成功/失败项，不重复创建；冲突先重新读取并合并。

5. 逐页读回核对标题、父级、关键字段、内容及链接，返回实际入口。

# 5. 进度数据与唯一来源

初始能力基线 v1.2 保持历史快照；当前掌握状态另设动态登记（可先在学科进度页维护）。每条记录包括知识点 ID、当前等级、课程状态、证据、评估日期、下次复习与下一行动。课程状态与掌握等级分离：未开始/进行中/待验收/已验收；Dashboard 仅汇总，不作为第二份独立事实来源。课程完成率=已通过必修 Unit 数/必修 Unit 总数；未评估不计为已掌握。日志保留实际事件，更新不覆盖历史。

# 6. 版本与安全

规范/课程采用 v主版本.次版本：结构或目标重大变化升主版本，增量内容升次版本；普通笔记记录修订日期及简短变更。不得在笔记、代码示例或公开网站存放 API Key、SSH 私钥、密码、私人数据；示例使用占位符。GitHub 公开仓库已接入，第二台设备同步尚待 Phase 04 验证；发布网站前核对访问权限和数据范围。
