# 技术课程设计规范 v1.0

创建日期：2026-11-26。适用 Python、Java、Spring、AI Agent、AI Infra 等技术课程。参考已归档的 [Python 课程大纲](https://chatgpt.com/space/page_6540eb5d120c81918e1bd0e2142029a0)。本规范用于设计课程，不代替具体学科大纲或知识笔记。

# 1. 明确目标与输入

先读取能力基线、知识盲区、长期路线、学习偏好与已有笔记；确认就业目标、当前主课、先修知识、目标等级和实践验收。区分自评、答题证据、独立实践与尚未评估。结合目标岗位的真实招聘要求和官方技术文档核验课程范围及版本；未调研时明确标记，不虚构市场结论。

# 2. 学习顺序与范围

同一阶段只安排一门主课：Python → Java → Spring，后续 AI Agent、AI Infra 按需。CS Fundamentals 穿插，Engineering 随项目嵌入。优先必备知识，区分核心、拓展、可延后内容；以阶段验收而非穷尽技术细节作为完成条件。时间按当前主课动态规划，不强制固定期限。

# 3. 课程分层设计

采用 Phase（学科阶段）→ Part（主题阶段）→ Unit（知识单元）→ Lesson（单课）四层结构。先建立先修依赖，再按基础恢复、核心开发、进阶原理、工程应用、综合验收逐步展开。Python 的 15 单元只是实例，Java、Spring 不必机械复制数量。

| 课程设计字段 | 要求 |
|---|---|
| Unit ID 与标题 | 稳定编号，便于追踪与引用 |
| 学习目标 | 可独立解释、实现或诊断的行为 |
| 前置知识 | 已有能力与需要补充的知识 |
| 核心概念 | What、Why、How，区分规范与实现 |
| 底层原理 | 结合源码、运行时、系统机制，注明版本 |
| 工程关联 | CS、Engineering、目标岗位与项目 |
| 实践任务 | 明确输入、输出、边界条件及验收 |
| 复习与面试 | 易错点、原理题、代码题、场景题 |
| 参考资料 | 官方文档优先，必要时核验来源 |
| 进度与证据 | 状态、练习链接、更新时间、待解决问题 |

# 4. 单课教学方法

每次讲解适量内容：概念与动机 → 示意图或最小可运行示例 → 预测代码结果 → 独立编程 → 调试与代码审查 → 口头解释 → 归档。先让学习者尝试，按需逐级提示；除非明确要求，不直接代写练习。允许查官方文档。错误要解释原因、定位步骤、修复及回归测试。根据实际回答调整深度。

# 5. 贯穿课程的递进项目

选取一个与就业相关、可以小步迭代的项目，先做最小可运行版本，每个单元增添能力。Python 实例：TaskHub，从 CLI 筛选排序逐步加入函数、OOP、SQLite、并发、重试、REST API、测试、日志、Docker。Java 可选择独立 Java 应用，Spring 可选择完整后端服务；项目主题由阶段目标决定。记录需求、接口、代码版本、测试证据、架构取舍和复盘。

# 6. 能力验收与进度

L0 尚未学习或需重建；L1 Learning；L2 Understood；L3 Practiced；L4 Mastered；NA 尚未评估。阅读不自动升级。单元验收检查正确性、边界、解释、独立编码及排错；未通过则补练。阶段验收要求独立交付可运行、可测试的核心项目，必要时部署，并能解释设计取舍。既有自评等级需在实践中验证。

# 7. 文档归档与版本管理

课程大纲保存于对应学科，长期顺序更新 Roadmap，当前任务更新 Dashboard。知识笔记、日志、实验、错题分别归档，复用现有四类模板。以稳定 ID 关联笔记与练习证据；已有页面增量更新，避免重复；记录创建/更新日期、版本和修改原因。仅在真实写入并读回后报告保存成功。Markdown 是可迁移格式；Space 原生页面不等于独立 .md 文件。

# 8. 新课程制作验收清单

- [ ] 读取现有基线、路线、知识盲区及同主题课程

- [ ] 明确目标岗位、主课顺序、版本与结业标准

- [ ] 核验官方资料与必要的岗位需求

- [ ] 设计 Part、Unit、Lesson 层级及先修依赖

- [ ] 为每个 Unit 设置独立实践和复习题

- [ ] 设计递进项目及阶段验收

- [ ] 将 CS 与 Engineering 关联到对应知识点

- [ ] 建立状态、证据与归档规则

- [ ] 保存至对应 Space 并读回验证

# 9. 可复用课程设计指令

请读取 Engineering Learning Hub 中的能力基线、知识盲区、最新版学习路线及本规范，为指定技术设计就业导向课程。以单主线学习为约束，按实际先修依赖划分 Part/Unit/Lesson；每单元给出目标、知识范围、底层原理、练习、验收及 CS/Engineering 关联；设计贯穿课程的递进项目与结业标准。区分必学和拓展内容，不假设已掌握未评估知识。优先核对官方文档与目标岗位要求。先给课程大纲，不预先生成全部课程笔记；检查已有文档并增量归档。

版本说明：v1.0 从 Python 课程设计实践提炼；目标岗位细分、课程时长和具体项目需逐科确定。
